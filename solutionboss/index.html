01Before the session

Set up access and run one test.

  1. Create the workshop link

    Name the workshop and the customer or team.

  2. Add shared context

    Set the business unit, objective and any constraint everyone must work inside.

  3. Set the recommendation scope

    Leave the full product portfolio eligible unless the sponsor has named a real constraint. Narrowing the list narrows what SolutionBoss may recommend.

  4. Create attendee access

    Set a short workshop password. Save both links: the participant link goes to the room; the owner link stays with you.

  5. Dry-run the flow

    Open the participant link in a private window, enter the workshop password, load the employee-onboarding example and submit once.

Do this before anyone joins. If the participant test or owner dashboard does not work, fix it before the workshop starts.

02During the session

Move from outcome to decision.

0–10 minFrame the outcomeWhose work changes, and what result matters?
10–25 minMap todayCapture steps, systems, information and hand-offs.
25–40 minSet boundariesWhat may happen automatically, what needs approval, and who owns the process?
40–55 minSubmitOne use case per participant or team through the participant link.
55–75 minCompare pathsOpen the owner dashboard, challenge assumptions, then confirm or revise each path.
75–90 minChoose pilotsAgree which cases move to validation and name an owner.

Spend the room's time on evidence and decisions, not on pitching a product.

03What each role sees

Participants get the decision. Owners get the detail.

Participant

Recommended path

Where to build, why, the MVP to try now and how to start.

Optional pilot plan

Readiness, supporting products, build steps, validation checks and an optional demo script.

Workshop owner

Private technical review

Architecture, components, AIDF trace, authority, risks, alternatives, detailed prerequisites and evidence.

Participants cannot open this view. Technical fields are excluded from their response.

04Inputs

Use what the field portal supports today.

Available in the portal

  • Guided intakeBest for most teams. Covers outcome, workflow and boundaries.
  • Free-form textFor an existing brief with users, current work, outcome, systems, actions, approvals and first pilot.
  • Participant workshop linkFor several people or teams submitting in one session.

Not in the field portal

  • Direct Mural board importConsolidate the relevant notes and paste the text into Free-form.
  • Board screenshot uploadNo screenshot upload control is exposed in the field portal.
05After the session

Close the room with owners and tests.

  • Review each complete intake and technical recommendation in the owner dashboard.
  • Confirm the path or record a revision.
  • Name a business owner for every selected pilot.
  • Write down unresolved data, identity and approval questions.
  • Agree the smallest validation test and the result that would count as success.
  • Export the workshop portfolio.

A recommendation is not approval to build. Verify tenant licensing, connector availability, identity, permissions and preview status before work starts.

06Facilitator notes

Keep the conversation factual.

Ask what happens today, who makes the decision, what information they trust and what result would justify a pilot. Do not open with a preferred product.

If the solution changes records, sends external messages, grants access or makes a consequential decision, name the human approver and the audit evidence required.

SolutionBoss may recommend conventional automation when rules and a fixed workflow are enough. Check every recommendation against the customer's tenant and current product boundaries.
