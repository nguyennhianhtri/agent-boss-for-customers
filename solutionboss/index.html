Prepare the workshop

Create the workshop before the session so the participant link and owner dashboard are ready.

1

Open Create workshop

Sign in to SolutionBoss, select Create workshop link, then name the workshop and customer or team.

2

Set the shared context

Add the business unit, workshop objective and any constraints everyone should work within.

3

Choose eligible products

Keep the full portfolio unless the sponsor has a real constraint. Narrowing the list changes what SolutionBoss is allowed to recommend.

4

Save both links

Send the participant link to the room. Keep the owner dashboard link for yourself; it contains the consolidated portfolio and review actions.

Before people join: open the participant link in a private browser window, test the password, load the employee-onboarding example, and submit one dry run.

Run the room

This sequence works for a live envisioning session. Spend the time on evidence and decisions, not product pitching.

0–10 min
Frame the outcome. Agree whose work should change and what result matters.
10–25 min
Map today. Capture the current steps, systems, information and hand-offs.
25–40 min
Set boundaries. Decide what may happen automatically, what needs approval and who owns the process.
40–55 min
Submit. Each team enters one use case through the participant link. SolutionBoss asks clarification only when the missing detail could change the recommendation.
55–75 min
Compare paths. Use the owner dashboard to review the portfolio, challenge assumptions and confirm or revise each path.
75–90 min
Choose the first pilots. Export the portfolio and assign an owner for validation.

Review and follow through

Owner dashboard

  • Filter by team and recommended solution.
  • Open the complete intake and recommendation.
  • Confirm the path or create a revision case.
  • Export the full portfolio to PDF.

Recommendation package

  • Microsoft solution family and rationale.
  • Architecture planes, components and ownership.
  • Now, next and later roadmap.
  • Validation checks, risks, evidence and starter files.

App analytics

  • Sessions, page views and API activity.
  • Submitted, completed, failed and interrupted cases.
  • Recommended-solution distribution.
  • Recent pseudonymous activity.

Close the workshop

  • Name the business owner for each selected pilot.
  • Record unresolved data, identity and approval questions.
  • Agree the smallest test and success threshold.
  • Do not treat the recommendation as production approval.

Facilitator notes

Push for facts

Ask what happens today, who makes the decision, what information they trust and what result would justify a pilot. Avoid starting with a preferred product.

Keep approvals explicit

If the solution changes records, sends external messages, grants access or makes consequential decisions, name the human approver and the audit evidence required.

Challenge unnecessary agents

SolutionBoss can recommend conventional automation when rules and workflow are enough. That is a valid outcome, not a failed agent workshop.

Use current product boundaries

The recommendation agent is grounded in AIDF, current Microsoft Learn material and a maintained product-boundary corpus. Verify tenant-specific licensing, preview status and connector availability before build.
