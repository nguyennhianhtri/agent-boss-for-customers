SolutionBoss · workshop quick start

From workshop setup to participant link

Use SolutionBoss to collect business use cases and recommend a Microsoft solution path without asking participants to know the products first.

solutionboss.trihq.dev ↗Portal password: AISolutioning
1

Create the workshop

Select Create workshop link and set:

  • Workshop and customer or team name
  • Objective and shared context
  • Eligible solution paths
  • A separate participant password
2

Check the intake

SolutionBoss generates the Business Use-Case Intake from those settings. Open the participant link in a private window and run the example once before the session.

3

Share the link

Send the participant link and workshop password to attendees. Keep the owner-dashboard link for the Workshop Lead. Participants do not need the main portal password.

What happens after submission

1 · Recommended pathPlain-language choice, first pilot and simple product descriptions.
2 · Build the first pilotFour readiness checks and a numbered build checklist.
3 · Validate the pilotSuccess checks and an optional demonstration script.
4 · Technical reviewArchitecture, AIDF trace, risks, alternatives and evidence.

Participants

Describe the business problem, current work, desired result, trusted information, actions, approvals and a useful first pilot. They start with the first three screens.

Workshop Lead / Chief Agent Officer

Review the consolidated portfolio, open Technical review, challenge the product and architecture, confirm or revise each path, and export the workshop portfolio.

Keep product choice open during intake. SolutionBoss may recommend conventional automation when a fixed workflow is enough. Verify tenant licensing, connectors, preview status, identity and permissions before build.
